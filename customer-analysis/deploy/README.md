# QCC Analytics — עדכון maba-dc2 לגרסה עם מסך תמחור מוצרים

חבילה לעדכון ההתקנה הקיימת ב־`C:\apps\qcc-analytics-deploy` (הותקנה 24/08/2026 מ־IT).
נבנתה 03/09/2026 מהריפו `Calibration-software\customer-analysis`.

## מה חדש

- **מסך "תמחור מוצרים"** (`/pricing`) — מערכת התמחור שרצה עד היום כשרת נפרד על פורט 4000,
  מאוחדת לתוך הדשבורד. שורה חדשה בסרגל הצד תחת "תמחור".
- זיהוי עמודות מתוקן בקבצי לקוח: עמודת מספר סידורי מזוהה, ובזכותה מוחזרים מספרי מ.ב.א.
- שתי תקלות שגרמו למספרי מ.ב.א. שגויים: מטמון שהחזיר תוצאה של מכשיר אחד לאחר, והכרעה
  שרירותית בין שני רישומים של אותו סידורי (27 אלף מקרים כאלה קיימים בפריוריטי).
- ה־build עצמאי: `node_modules` כבר לא נדרש (נשאר שם, פשוט לא בשימוש).

## התקנה

```powershell
cd C:\apps\qcc-server-deploy-20260903
powershell -ExecutionPolicy Bypass -File .\Install-QCCAnalytics.ps1 -WhatIf   # תצוגה מקדימה
powershell -ExecutionPolicy Bypass -File .\Install-QCCAnalytics.ps1           # לביצוע
```

PowerShell **כמנהל**.

הסקריפט מאתר בעצמו את מה שמריץ את האפליקציה — **שירות Windows או משימה מתוזמנת**. שתי
האפשרויות קיימות: `2-install-service.ps1` של IT מתקין שירות NSSM אם NSSM זמין, ואחרת נופל
למשימה מתוזמנת בשם `QCCAnalytics` שרצה תחת SYSTEM. אם הזיהוי לא מוצא או מוצא כמה:

```powershell
.\Install-QCCAnalytics.ps1 -Name QCCAnalytics -Target "C:\apps\qcc-analytics-deploy\app"
```

**סדר הפעולות:** עצירה ← גיבוי `dist_bak_<תאריך>` ← החלפת `dist` ← העתקת `data\pricing`
(בלי לדרוס קיים) ← עדכון `.env` (עם גיבוי `.env.bak_<תאריך>`) ← הפעלה ← ארבע בדיקות.

## מה משתנה ב־.env

| מפתח | פעולה |
|------|-------|
| `PRICE_SOURCE`, `PRICE_LIST_FILE`, `FUZZY_THRESHOLD` | נוספים |
| `PRICING_DATA_DIR` | נוסף, בנתיב מלא לתיקיית הנתונים |
| `ANTHROPIC_API_KEY` | נוסף (אופציונלי, ראה למטה) |
| `DASHBOARD_USER` / `DASHBOARD_PASSWORD` | **מוחלפים** ל־`mba` / `1234` |
| `DATABASE_URL`, `SQL_*`, `PORT`, `DATA_SOURCE` | לא נגעים |

**`PRIORITY_DB_*` לא נוספים בכוונה.** מסך התמחור קורא את פריוריטי דרך אותם פרטים שהדשבורד
כבר משתמש בהם (`SQL_SERVER_ADDR` / `SQL_UID` / `SQL_PWD`) — אלה שנבדקו ועובדים על השרת הזה.
הוספת זוג פרטים שני הייתה דורסת הגדרה עובדת בהגדרה שלא נבדקה שם מעולם.

## שלוש אזהרות

**1. שם המשתמש והסיסמה של כל המשתמשים משתנים.** בגרסה הקיימת כבר נדרשת הזדהות (ברירת המחדל
של IT היא `DASHBOARD_USER=qcc` עם סיסמה שהם קבעו). ההתקנה **מחליפה** אותם ל־`mba` / `1234`.
מי שנכנס לדשבורד היום עם הפרטים הישנים ייתקע — צריך להודיע מראש.
לשינוי: ערוך את `env-additions.txt` **לפני** ההרצה.

**2. `data\pricing` היא נתונים חיים.** שם יושבות 2,652 ההתאמות שנלמדו — כל תיקון שמשתמש אישר.
בהתקנה ראשונה הן מועתקות; בהרצה חוזרת הסקריפט **לא ידרוס** קבצים קיימים. לגבות את התיקייה
הזו, לא לשחזר אותה מ־build.

**3. מפתח ה־Anthropic ללא יתרה.** העשרת ה־AI (זיהוי פריטים לא מוכרים בחיפוש אינטרנט) לא
תעבוד עד לטעינת יתרה. שכבה אופציונלית; המערכת מכבה אותה אוטומטית אחרי הכישלון הראשון במקום
לנסות שוב לכל פריט, ואחרי טעינת יתרה היא חוזרת בהפעלה מחדש.

## בדיקה אחרי ההתקנה

הסקריפט מסיים ב־`DEPLOY OK` או באזהרות, אחרי שבדק: הדשבורד עונה, המחירון נטען (875 פריטים),
פריוריטי מחובר (~44,700 דגמים), ושאילתה מול בסיס הנתונים עוברת.
**אם `priority: NOT connected` — עצור.** בלי זה אין מספרי מ.ב.א., וזו כל מטרת המסך.

בדיקה ידנית:

1. `http://localhost:5000/pricing` — "פריוריטי מחובר" ירוק, "מחירון (875 פריטים)".
2. בחר לקוח (הקלד `10251` = מובילאיי) והעלה קובץ עם עמודת מספר סידורי.
3. ודא שעמודת "מס׳ מ.ב.א. אחרון" מתמלאת.
4. "הורדה לאקסל", ואז:

```powershell
node C:\apps\qcc-server-deploy-20260903\check-pricing-export.mjs "<הקובץ>.xlsx"
```

תקין = `OK   every MABA number belongs to exactly one serial number`.

5. הבדיקה הספציפית: סידורי `MY63001093` צריך להראות `170312-7` ו־`2512750/22` — לא `2505548/13`.


כ־`dist_failed_<תאריך>`. `data\pricing` לא נוגעים בה. ה־.env הישן: `.env.bak_<תאריך>`.
