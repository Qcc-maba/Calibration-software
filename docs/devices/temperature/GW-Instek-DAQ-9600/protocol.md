# GW Instek DAQ-9600 — פרוטוקול

מערכת רכישת נתונים (mainframe) עם מודד 6½ ספרות פנימי ושלושה חריצי מודולים. אצלנו: שני כרטיסי
**DAQ-901** (מרבב 20 ערוצים), כלומר עד 40 ערוצים — לוגר טמפרטורה רב-ערוצי. MBA-1058.
המקור: **DAQ-9600 User Manual** (GW Instek, 357 עמ'), פרק Remote Control, עמ' 177–333.

> **סטטוס: אומת מקצה לקצה מול החומרה — 2026-11-26.**
> יחידה `GEY150853` (MABA **31-83**), קושחה `M1.07_S1.02`, USBTMC.
> `*IDN?` → הגדרה → `READ?` → פיצוי לפי תעודת **21-675** (5 תרמוקופלי K על 101–105)
> → `BroadcastAllMeasurements` → WebSocket (`LoggerData`, `Units:"Celsius"`, ערוצים 1–5, כל 10 שניות).
> **PT-100 ו-DC volts:** הפקודות אומתו (המכשיר קיבל אותן בלי שגיאה), אבל **לא חובר חיישן** — אין
> עדיין קריאה אמיתית של שניהם. גם צימוד 4-חוטים n↔n+10 לא אומת עם PT-100 מחובר.

## זיהוי

- **תשובת `*IDN?` בפועל:** `GWInstek,DAQ-9600,GEY150853,M1.07_S1.02` (בלי רווחים, מסתיים ב-`\n` בלבד).
- **זיהוי:** `HardwareDeviceHost.IsGwInstekDaq9600` — יצרן **וגם** דגם, בלי תלות ברישיות, אחרי הסרת
  רווחים/מקפים/קווים תחתונים. ה-SN הוא `DAQ-9600`.
- ⚠️ **הענף חייב לבוא לפני `res.Contains("Instek")`.** הענף הכללי מוסר את המכשיר ל-`InstekBLCore` —
  BL שמעולם לא הושלם, שבו `TRIG:COUN INF` ואחריו `READ?` שלעולם לא חוזר.
- ⚠️ **SCPI ID = User** (תפריט Interface) גורם למכשיר לענות בשם שהוגדר ידנית (`SYST:SCP:MODE COMP`),
  ואז הוא לא מזוהה. ביחידה שלנו: `NORMAL`.
- **מחלקות:** `Device/Temperature/Daq9600BL.cs`, `BLCore/Temperature/Daq9600BLCore.cs`,
  פענוח ופקודות טהורים ב-`Device/Temperature/Daq9600Readings.cs`, טסטים ב-`VCT.Core.Tests/Daq9600Tests.cs`.
- **ברשומות:** `MeasurementDevices` מכיר את היחידה כ-**31-83**, אבל:
  הרשומה מופיעה **שלוש פעמים** (ID 794, 830, 866), והמספר הסידורי שמור כ-`GEY 150853` — **עם רווח**,
  בעוד המכשיר מדווח `GEY150853`. אותה כפילות גם ב-31-80 ו-31-81.

## חיבור פיזי — USBTMC (ברירת המחדל)

| | |
|---|---|
| **מחרוזת משאב** | `USB0::0x2184::0x007F::GEY150853::INSTR` |
| **מזהי USB** | `VID_2184` (GW Instek) / `PID_007F`, class `FE/03/01` = USBTMC |
| **שכבה** | `VisaCom` — נמצא אוטומטית ב-`viFindRsrc("USB?*INSTR")`, **בלי שינוי הגדרות** |
| **דרישה** | **NI-VISA 32-bit** (`SysWOW64\visa32.dll`) — השרת x86. בלעדיו: Device Manager code 28 |

- בלי VISA המכשיר "קיים" ב-Windows ושום דבר לא עונה. ההתקנה ארכה מעל חצי שעה על המחשב הנייד
  (274 חבילות NI). אחריה VISA עבד **לפני** אתחול. ראה `Installer/DRIVERS.md` ו-`{app}\drivers\README-NI-VISA.txt`.
- **USBCDC:** בתפריט Interface אפשר להפוך את יציאת ה-USB ל-COM וירטואלי (בלי VISA). לא נוסה ולא נתמך כאן.
- **LAN:** TCP raw port 5025, Telnet 5024 (לפי המדריך). VCT עדיין לא מתחבר החוצה למכשיר רשת — ראה MBA-1058, ממצא 5.
- רק ממשק אחד פעיל בכל פעם (USB / GPIB / LAN נבחרים בתפריט).

## מספור ערוצים

ערוץ במכשיר = **חריץ × 100 + הדק**. האפליקציה ממספרת 1, 2, 3… ו**דורסת** את רשימת הערוצים בהגדרות,
ולכן ההגדרות מחזיקות את מספור האפליקציה וה-BL מתרגם:

| חריץ | הדקים | ערוצי מכשיר | ערוצי אפליקציה |
|---|---|---|---|
| 1 (DAQ-901 `GPZ160849`) | 1–20 | 101–120 | 1–20 |
| 2 (DAQ-901 `GPZ160850`) | 1–20 | 201–220 | 21–40 |
| 3 (ריק — `SYST:CTYP? 3` → `GWInstek,0,0,0`) | — | 301–320 | 41–60 |

- הדקים 21, 22 בכל כרטיס הם ערוצי זרם — לא בשימוש.
- **4 חוטים (PT-100):** הדק n מצומד ל-n+10, ולכן רק הדקים 1–10 של כרטיס יכולים להיות ערוץ 4-חוטים.
  ערוץ 11–20 שנבחר במצב הזה נדחה ונרשם בלוג.
- ⚠️ **המכשיר תמיד סורק בסדר עולה.** `ROUT:SCAN (@105,101,109)` נקרא חזרה כ-`(@101,105,109)`
  ו-`READ?` עונה בסדר הזה. ה-BL ממפה תשובות לפי הרשימה הממוינת, לא לפי הסדר שנשלח.

## הגדרה — רצף אחד, פקודה אחרי פקודה

כל פקודה נשלחת כשהקודמת יצאה (`SendSetup`), ולא צעד מכונת-מצבים לכל פקודה: הבקשות נכנסות לתור
על pool thread, ושתי פקודות יכולות לעקוף זו את זו (מה שה-Hydra למד ב-MBA-967).

```
ABOR
*CLS
CONF:TEMP TC,K,(@101,102,103,104,105)      # T / R / S באותה צורה
TEMP:TRAN:TC:CHEC ON,(@101,...)             # חובה - ראה למטה
UNIT:TEMP C,(@101,...)
TEMP:NPLC 1,(@101,...)                       # FAST=1, SLOW=12
FORM:READ:CHAN OFF
FORM:READ:TIME OFF
FORM:READ:UNIT OFF
FORM:READ:ALAR OFF
ROUT:SCAN (@101,...)
TRIG:SOUR IMM
TRIG:COUN 1
SYST:ERR?                                    # -> +0,"No error" (נרשם בלוג)
```

| פונקציה | במקום שלוש שורות ה-TEMP |
|---|---|
| PT-100, 4 חוטים | `CONF:FRES 1e3,(@..)` + `FRES:NPLC n,(@..)` |
| PT-100, 2 חוטים | `CONF:RES 1e3,(@..)` + `RES:NPLC n,(@..)` |
| DC volts | `CONF:VOLT:DC AUTO,(@..)` + `VOLT:DC:NPLC n,(@..)` |

טווח 1 kΩ קבוע ל-PT-100: הוא משתרע על ~18–390 Ω בין −200 ל-850 °C, וטווח 100 Ω נחתך.

**כל הרצף אומת על היחידה** — שגיאה `+0` אחרי כל קבוצה.

### ⚠️ זיהוי תרמוקופל פתוח — `TC:CHEC ON`

- **כבוי אחרי כל `CONF:TEMP`.**
- בלעדיו, תרמוקופל **R פתוח קרא 789 °C ו-S פתוח 292 °C** — מספרים שנראים אמיתיים.
- איתו, כל כניסה פתוחה (K, T, R, S) קוראת `+9.90000000E+37`, וה-BL מסמן את הערוץ כמנותק.

### ⚠️ `TRIG:COUN 1`, לא `INF`

`READ?` = INIT + FETCh. עם ספירה אינסופית הוא לא חוזר לעולם והסשן נתקע. זה היה הבאג של `InstekDeviceBL`.

### `+261 "Not able to execute while scan initiated"`

נראה **פעם אחת** בזמן הבדיקות (query על ערוץ מחוץ לרשימת הסריקה, מיד אחרי `CONF`) ולא שוחזר
בחמישה ניסיונות. לכן `ABOR` + `*CLS` פותחים כל אתחול, ו-`SYST:ERR?` סוגר אותו ונרשם. לא ידוע מה הגורם.

## קריאה

```
READ?  ->  +2.14422233E+01,+2.17258911E+01,+2.16123355E+01,+2.17270551E+01,+2.16997316E+01\n
```

- ערך NR3 לכל ערוץ, מופרד בפסיקים, `\n` בלבד בסוף.
- 5 תרמוקופלים ב-1 PLC: **330–440 ms**. 11 ערוצים עם שניים ב-12 PLC: 2.3 s.
- `Daq9600Readings.TryParseReadings` מקבל רק תשובה שכל ערכיה מתפענחים **ומספרם שווה למספר הערוצים**.
  תשובה חלקית הייתה שמה ערכים על ערוצים שגויים — היא נזרקת כולה.
- `+9.9E37` = כניסה פתוחה / חריגת טווח → `ChannelDisconnected` פעם אחת, ו-`DataRestored` כשחוזר.
- ה-BL שולח `READ?` אחד כל `Interval` שניות (ברירת מחדל 10), מתוזמן מתחילת הסריקה הקודמת.

## פיצוי — כמו ב-Hydra 2625A

| פונקציה | מה נשלח |
|---|---|
| תרמוקופל | °C מהמכשיר, מתוקן לפי טבלת התיקון של החיישן המשויך לערוץ (`CalcDeviationForTemperature`) |
| PT-100 | Ω מהמכשיר → °C לפי מקדמי ITS-90 של החיישן המשויך (`CalcResistanceToTemperatureITS90`), כמו ב-34401A |
| DC volts | וולט, כפי שנמדד, בלי פיצוי |

- **החיישן לערוץ:** מה שהאפליקציה שייכה (`SensorsAssociation`), ואם לא שייכה — `Masters[0]` מההגדרות.
- **אין חיישן, אין תעודה, או `WrongValue` (9999)** → הקריאה **לא נשלחת**, שורת לוג אחת לחיישן,
  והתראת `CorrectionUnavailable` לערוץ. ערך לא מתוקן לא נשלח לעולם כאילו היה מתוקן (MBA-1007).
- הלוגיקה הזו הוצאה ל-`ChannelCertificates` / `ChannelDisconnects` (`Device/Temperature/ChannelCertificates.cs`).
  `Hydra2DeviceBL` עדיין מחזיק עותק משלו — העברתו לשם היא שינוי נפרד ב-BL מאומת.
- ⚠️ PT-100 ששויך **באמצע ריצה** מומר רק מהאתחול הבא (Confirm), כי טעינת הרקע בודקת טבלת תיקון ולא מקדמים.

## הגדרות (`HydraBL_Settings.json`, משפחה `Daq9600`)

```json
"Daq9600": {
  "MeasurementRate": 1,        // 1 = FAST (1 PLC), 0 = SLOW (12 PLC)
  "Channels": [1, 2, 3, 4, 5], // מספור אפליקציה
  "Interval": 10,              // שניות בין סריקות
  "Sensor": { "MeasureType": 0, "SensType": 0, "ThermocoupleType": 1 },
  "MaxNumOfChannels": 60,
  "Masters": []
}
```

- `SensType`: 0 = תרמוקופל, 1 = RTD (2 חוטים), 2 = FRTD (4 חוטים). `ThermocoupleType`: K=1, T=3, R=5, S=6.
  DC volts: `SensType` −1 ו-`MeasureType` 8 (`VoltageDC`).
- ⚠️ בתחנה משודרגת הקובץ נשמר מהגרסה הקודמת ואין בו `Daq9600`. `Daq9600BL.FillMissingFromDefaults`
  משלים כל שדה חסר מ-`CreateDefaultSettings()` במקום לרוץ עם null.

## בטיחות

ה-DAQ-901 רק **ממתג כניסות**. אין במכשיר מוצא שמחשמל משהו; ה-BL לא נוגע ב-Digital I/O או ביציאות
ההתראה. טסט (`NoSetupCommandDrivesAnOutput`) מוודא שאף פקודת הגדרה לא מתחילה ב-`OUTP`/`DIG`/`SOUR`/`ROUT:CLOS`.
מקסימום מבוא לפי המדריך: 300 V.
