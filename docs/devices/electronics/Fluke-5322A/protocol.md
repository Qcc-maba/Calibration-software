# Fluke 5322A — פרוטוקול

מכייל בודקי בטיחות חשמלית (Multifunction Electrical Tester Calibrator).
המקור: **5322A Operators Manual** הרשמי (`5322A___openg0000.pdf`).

> **סטטוס: ערכת הפקודות אומתה מול החומרה — 2026-09-08, GPIB כתובת 2.**
> היחידה: `FLUKE,5322A,655320925,1.018`, `*OPT? → 1,1,1,0,0,0`.
> כל חמש השאילתות שה-BL משתמש בהן התקבלו עם תור שגיאות ריק (`0,No error`).
> **לולאת המדידה טרם רצה מול יעד כיול אמיתי.**

## ⚠⚠ שאילתת setpoint **משנה את מצב המכשיר**

המלכודת החמורה ביותר במכשיר הזה, והיא לא נראית כמלכודת: **`SAF:<פונקציה>?` אינה
קריאה בלבד — היא בוחרת את הפונקציה.** הוכח חי 2026-09-08:

```
SAF:MODE?  ->  GBR
SAF:LOOP?  ->  1686.1e+00
SAF:MODE?  ->  LOOP     ← השאילתה העבירה את המכשיר
SAF:GBR?   ->  1686.1e+00
SAF:MODE?  ->  GBR      ← והחזירה אותו
SYST:ERR?  ->  0,No error
```

לכן לולאת הקריאה שואלת קודם `SAF:MODE?` ומבקשת setpoint **רק עבור הפונקציה
שהמכשיר כבר נמצא בה** (`Fluke5322aReadings.IsGroundBondMode`). בלי השער הזה הסקירה הייתה
גוררת את המכייל ל-Ground Bond כל שתי שניות ודורסת את בחירת המפעיל בפאנל. זה באג
שהיה ב-BL ותוקן רק בזכות חיבור לחומרה — אין דרך לגלות אותו מהמדריך.

> ⚠️ **ה-5322A וה-5522A הם שני מכשירים שונים.** ה-5522A הוא מכייל רב-תכליתי (מתח/זרם/התנגדות),
> ה-5322A הוא מכייל בודקי בטיחות חשמלית (ground bond, בידוד, זרם דליפה, RCD, hipot). יש להם ערכות
> פקודות שונות ו-BL נפרד לכל אחד.

## ⚠️ זיהוי — שם הדגם הוא הגדרה בתפריט

המדריך מפורש בנקודה הזו:

| מצב `5320A Emulation` | תשובת `*IDN?` |
|---|---|
| כבוי | `FLUKE,5322A,<serial>,<firmware>` |
| דלוק | `FLUKE,5320A,<serial>,<four firmware parts>` |

**אותו מכשיר פיזי מדווח דגם אחר לפי הגדרה בפאנל הקדמי.** לכן `HardwareDeviceHost.IsFluke5322a`
מתאים **את שני האיותים** ומנרמל את שניהם ל-SN יחיד `5322A`. בלי הנרמול הזה, מפעיל שמדליק אופציה
בתפריט מוציא את המכשיר מהשרת — בלי שגיאה בשום מקום.

- **SN שנקבע:** `5322A` (משני האיותים)
- **מחלקת BL:** `Systems/Hydra-Group/ComServer/ComServerBL/Device/Electronics/Fluke5322aBL.cs`
- **BLCore:** `BLCore/Electronics/Fluke5322aBLCore.cs` · **פענוח:** `Device/Electronics/Fluke5322aReadings.cs`

הזיהוי נעשה **לפי הדגם ולא לפי היצרן**: גם לוגרי ה-Hydra וגם ה-5522A עונים `FLUKE,...`, והענף
הקיים חותך 11 תווים. ענף `5322A` הוצב לפניו, בדיוק כמו ענף ה-5522A.

## חיבור פיזי

שלושה ממשקים: **GPIB**, **RS-232**, ו-**USB**.

> ⚠️ **רק ממשק אחד פעיל בכל רגע** (`Setup > Interface > Active interface`) — בדיוק המלכודת של
> ה-5522A. כל עוד ה-GPIB הוא הממשק הפעיל, פורט ה-USB **מת**, והסימפטום הוא שתיקה מוחלטת ולא שגיאה.

### USB

מוצג כפורט COM וירטואלי, **8-N-1**.

> ⚠️ **`SYST:REM` הוא חובה לפני כל פקודה אחרת.** דרך USB המכשיר נשאר במצב מקומי ומתעלם מהכול עד
> שיקבל אותה — אותה דרישה בדיוק שיש ל-Agilent 34401A ב-RS-232. `*RST` שנשלח לפני `SYST:REM` נזרק
> בשקט, והאתחול רק *נראה* כאילו רץ.

זו הסיבה ש-`SYST:REM` היא **הפקודה הראשונה ברצף האתחול**, ויש טסט שמאמת את הסדר הזה.

## ⚠️⚠️ בטיחות — הכלל שה-BL אוכף

**`OUTP ON` מוציא את האות למהדקים בפועל.** מכייל בודקי בטיחות מייצר, בין השאר, רמות **hipot**
ו-**flash test**.

- **`OUTP ON` לא נמצא באתחול ולא בלולאת הקריאה.** הוא נבנה (יעד כיול זקוק לו) אבל מונפק רק בפקודה
  מפורשת — אותו כלל בדיוק כמו `Datron9100Commands.BuildOutputOn` ו-`Fluke5522aCommands.BuildOperate`.
- **רצף האתחול:** `SYST:REM` → `*RST` → `*CLS` → **`OUTP OFF`**. ה-`OUTP OFF` המפורש בסוף הופך את
  המצב המנוטרל להצהרת כוונה ולא לתוצר-לוואי של ה-reset.
- **`SAF:GBR` רק בוחר ערך** ואינו מוציא דבר — המוצא כבוי עד `OUTP ON`.
- יש טסטים שמאמתים את התכונות האלה: שאף פקודת אתחול אינה `OUTP ON`, שהאתחול מתחיל ב-`SYST:REM`
  ומסתיים ב-`OUTP OFF`, ושפקודת setpoint אינה נושאת עמה הפעלת מוצא.

## ערכת הפקודות

שים לב: המוצא נשלט ב-**`OUTPut[:STATe] ON|OFF`** — **לא** ב-`OPER`/`STBY` של ה-5522A.

### קריאה בלבד

| פקודה | תשובה לפי המדריך |
|---|---|
| `*IDN?` | `FLUKE,5322A,<serial>,<firmware>` או `FLUKE,5320A,...` |
| `*OPT?` | האופציות המותקנות |
| `OUTP?` | `ON` / `OFF` |
| `SAF:MODE?` | הפונקציה הנבחרת |
| `SAF:GBR?` | ה-setpoint, אקספוננציאלי — הדוגמה של המדריך: 50.54mΩ מוחזר כ-`50.54e-03` |

### שינויי מצב בטוחים

`SYST:REM` · `*RST` · `*CLS` · `OUTP OFF`

### בחירת ערך (לא מחשמל)

`SAF:GBR <ohms>` · `SAF:GBR:RPOS <0..15>` (בחירה מתוך 16 ההתנגדויות, 25mΩ עד 2kΩ)

### ⚠️ מחשמל

`OUTP ON` — ורק דרכו.

## תת-מערכת `[SOURce]:SAFety` — הפונקציות

`SAF:MODE?` מחזיר אחת מאלה:

| קוד | פונקציה |
|---|---|
| `GBR` / `GBOP` | Ground Bond Resistance / Open |
| `HRES` / `HRF` / `HRSH` | התנגדות גבוהה / 100GΩ קבוע / קצר |
| `LRES` / `LROP` / `LRSH` | התנגדות נמוכה / פתוח / קצר |
| `IDAC` / `IDS` / `IDSS` / `IDSO` / `IDP` / `IDD` | זרם דליפה — אקטיבי / תחליפי / קצר / פתוח / פסיבי / דיפרנציאלי |
| `RCDT` / `RCDC` / `RCDP` | RCD — זמן ניתוק / זרם ניתוק / PAT |
| `LIN` / `LOOP` | עכבת קו / עכבת לולאה |
| `VOLT` / `MET` | מכייל מתח / מודד |
| `HIPL` / `HIPT` | Hipot — זרם דליפה / טיימר |
| `FLI` / `FLII` | Flash Class I / Class II |

## פענוח תשובות

`Fluke5322aReadings` הוא פענוח טהור (בלי חומרה) וכולו מכוסה בטסטים:

- **`TryParseValue`** — קורא את הצורה האקספוננציאלית. קריאה שלא נפרסת **נזרקת ולא הופכת ל-0**, כי
  0 הוא setpoint לגיטימי לחלוטין על מכייל וברגע ששודר אי אפשר להבדיל בין השניים.
- **`IsOutputLive`** — קורא גם `ON`/`OFF` וגם `1`/`0`. תשובה בלתי קריאה מדווחת כ"לא מחובר", כלומר
  נוטה לצד המנוטרל.
- **`UnitsForMode`** — ממפה פונקציה ליחידה. פונקציית לא-מוכרת נופלת ל-**התנגדות** ולא למתח: ground
  bond ושתי סימולציות ההתנגדות הן מה שהמכשיר הזה עושה כמעט כל הזמן, ופונקציית המתח היא אחת מתוך
  עשרים ומשהו. פונקציות הטיימר (`RCDT`, `RCDP`, `HIPT`) הן שניות — גודל שאין לו שם בשפת השידור —
  ולכן נשארות **בלי תווית** במקום לקבל תווית של משהו שהן לא.

## לולאת הקריאה

`OUTP?` (דיווח מצב מוצא ללוג) → `SAF:MODE?` → **אם ורק אם המצב הוא `GBR`** → `SAF:GBR?` → שידור.

בכל פונקציה אחרת הלולאה **לא משדרת כלום** ורק רושמת את המצב ללוג — ראה האזהרה
בראש המסמך: שאילתת setpoint הייתה מעבירה את המכשיר לפונקציה הזו.

מכייל הוא **מקור ולא לוגר**: מה שהוא "מודד" הוא הערך שהוא מוגדר לייצר, וזה מה שכיול משווה אליו את
קריאת המכשיר הנבדק.

## הגדרות

```json
"Fluke5322a": {
  "Channels": [ 1 ],
  "MaxNumOfChannels": 1,
  "Masters": [],
  "Sensor": { "MeasureType": 2, "SensType": -1 }
}
```

`MeasureType: 2` = `Resistance` → היחידה המשודרת `Ohm`. התנגדות ולא מתח, מאותו נימוק שב-`UnitsForMode`.

## פתוח

- **לולאת המדידה טרם רצה מול יעד כיול אמיתי.** ערכת הפקודות אומתה, אבל הערך שנקרא עד
  כה הוא setpoint של המכשיר במצב מנוחה, לא מול מכשיר נבדק.
- **הפעלת מוצא מרחוק לא מחווטת לפקודה מהאפליקציה** — כמו בכל שאר המקורות כאן.
- ה-BL קורא רק את setpoint ה-ground bond (`SAF:GBR?`). שאר עשרים הפונקציות מזוהות ומדווחות ללוג
  דרך `SAF:MODE?` אבל אין להן שאילתת setpoint משלהן — להוסיף לפי הצורך כשיהיה יעד כיול אמיתי.
