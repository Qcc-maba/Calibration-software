# Meatest M-142 — פרוטוקול

מכייל רב-תכליתי (Multifunction Calibrator) **שיש בו גם מודד פנימי**.
המקור: המדריך הרשמי של היצרן — `https://www.meatest.com/files/download/man/m142m.pdf`

> **סטטוס: נכתב מהמדריך בלבד — טרם אומת מול החומרה.**
> כל מחרוזת תשובה במסמך הזה היא הצורה שהמדריך מתעד, לא לכידה מהמכשיר. יש לאמת בחיבור הראשון.

## זיהוי

- **תשובת `*IDN?` (לפי המדריך):** `MEATEST,M-142,412341,4.6`
- **SN שנקבע:** `M-142`
- **מחלקת BL:** `Systems/Hydra-Group/ComServer/ComServerBL/Device/Electronics/MeatestM142BL.cs`
- **BLCore:** `BLCore/Electronics/MeatestM142BLCore.cs` · **פענוח:** `Device/Electronics/MeatestM142Readings.cs`

הזיהוי (`HardwareDeviceHost.IsMeatestM142`) דורש **גם את שם היצרן וגם את הדגם**. התאמת הדגם מנרמלת
רווחים ומקפים (כדי ש-`M-142` ו-`M 142` ייחשבו לאותו דבר), וזו התאמה רופפת מספיק שבלי בדיקת היצרן
היא הייתה יכולה לתפוס תשובה לא קשורה שמכילה את הספרות האלה. בדיקת הדגם היא גם מה שמונע מ-**M-140**
ומ-**M-143** — מכשירים אחרים עם יכולות אחרות — להיתפס ל-BL הזה.

## חיבור פיזי

שני ממשקים, שניהם סטנדרטיים ביחידה:

| | GPIB | RS-232 |
|---|---|---|
| **כתובת / הגדרות** | כתובת **2** מהיצרן | **8-N-1**, 150–19200 baud (נבחר מתפריט המכשיר) |
| **כבל** | GPIB רגיל | ⚠️ **כבל ישר 1:1** |
| **בקרת זרימה** | — | XON/XOFF אופציונלי |

> ⚠️ **הכבל הוא לא אותו כבל של ה-5522A.** ה-M-142 דורש כבל **ישר**, בעוד ה-Fluke 5522A דורש
> **null-modem**. החלפה ביניהם מייצרת בדיוק את אותה שתיקה מוחלטת שקיבלנו מה-5522A לפני החלפת הכבל —
> בלי הודעת שגיאה בשום מקום.

## ⚠️⚠️ בטיחות — הכלל שה-BL אוכף

**`OUTP ON` מחבר את המהדקים בפועל. עם אופציית סליל 50 הכריכות (`OUTP:ISEL HI50`) מדובר ב-1000A.**

- **`OUTP ON` לא נמצא באתחול ולא בלולאת הקריאה.** הוא נבנה (יעד כיול זקוק לו) אבל מונפק רק בפקודה
  מפורשת — אותו כלל בדיוק כמו `Datron9100Commands.BuildOutputOn` ו-`Fluke5522aCommands.BuildOperate`.
- **רצף האתחול דוחף לכיוון ההפוך:** `*RST` → `*CLS` → **`OUTP OFF`**. ה-`OUTP OFF` המפורש בסוף הופך
  את המצב המנותק להצהרת כוונה ולא לתוצר-לוואי של ה-reset.
- **פקודות `SOUR:` רק בוחרות ערך** ואינן מחברות דבר — המהדקים מנותקים עד `OUTP ON`.
- יש טסטים שמאמתים את התכונות האלה: שאף פקודת אתחול אינה `OUTP ON`, שהאתחול מסתיים ב-`OUTP OFF`,
  ושאף פקודת setpoint אינה נושאת עמה הפעלת מוצא.

## ערכת הפקודות

### קריאה בלבד

| פקודה | תשובה לפי המדריך |
|---|---|
| `*IDN?` | `MEATEST,M-142,412341,4.6` |
| `*OPC?` | סיום פעולה |
| `OUTP?` | `ON` / `OFF` |
| `SOUR:FUNC:SHAP?` | צורת הגל הנבחרת |
| `MEAS?` | הערך הנמדד, אקספוננציאלי — הדוגמה של המדריך: 20.5 מוחזר כ-`2.050000e+001` |
| `MEAS:CONF?` | `VOLT` \| `CURR` \| `MVOLT` \| `RES` \| `FREQ` \| `TEMPerature:RTD` \| `TEMPerature:THERmocouple` \| `OFF` |
| `SOUR:VOLT?` / `SOUR:CURR?` / `SOUR:RES?` / `SOUR:FREQ?` | ה-setpoint הנוכחי |

### שינויי מצב בטוחים

`*RST` · `*CLS` · `OUTP OFF`

### בחירת ערך (לא מחשמל)

`SOUR:VOLT` · `SOUR:CURR` · `SOUR:RES` · `SOUR:CAP` · `SOUR:FREQ` · `SOUR:FUNC:SHAP`

### ⚠️ מחשמל

`OUTP ON` — ורק דרכו. `OUTP:ISEL HIGH|HI50` בוחר בין המוצא הרגיל לסליל 1000A.

## מה מייחד את המכשיר הזה — הוא גם מודד

זה ההבדל המהותי מול ה-Datron 9100 ומול ה-Fluke 5522A. שניהם **מקורות בלבד**: כל מה שהם יכולים
"לדווח" הוא ה-setpoint שהם מוגדרים לייצר. ל-M-142 יש **מודד פנימי**, ולכן הוא יכול לדווח ערך
שהוא באמת מדד.

לכן לולאת הקריאה שואלת קודם מה מצב המודד:

```
OUTP?  ──►  לוג: מהדקים מחוברים / מנותקים
   │
MEAS:CONF?
   ├── ≠ OFF ──►  MEAS?          ──►  שידור מדידה אמיתית
   └── = OFF ──►  SOUR:<פונקציה>? ──►  שידור ה-setpoint
```

**תשובה שלא ניתן לקרוא נחשבת ל-`OFF`**, כך שה-BL נופל חזרה ל-setpoint במקום לשדר מדידה שאין לו
בסיס לעמוד מאחוריה.

## פענוח תשובות

`MeatestM142Readings` הוא פענוח טהור (בלי חומרה) וכולו מכוסה בטסטים:

- **`TryParseValue`** — קורא את הצורה האקספוננציאלית. קריאה שלא נפרסת **נזרקת ולא הופכת ל-0**, כי
  0V הוא setpoint לגיטימי לחלוטין על מכייל וברגע ששודר אי אפשר להבדיל בין השניים.
- **`IsOutputLive`** — קורא גם `ON`/`OFF` וגם `1`/`0`. תשובה בלתי קריאה מדווחת כ"לא מחובר", כלומר
  נוטה לצד המנוטרל.
- **`UnitsForMeterMode`** — ממפה את מצב המודד ליחידה. `MVOLT` נשאר בשפת ה-`Volt`: הערך עצמו נושא
  את הסקאלה, ויחידת מתח שנייה הייתה מפצלת גודל אחד לשני שמות בהמשך השרשרת.

## הגדרות

```json
"MeatestM142": {
  "Channels": [ 1 ],
  "MaxNumOfChannels": 1,
  "Masters": [],
  "Sensor": { "MeasureType": 8, "SensType": -1 }
}
```

`MeasureType: 8` = `VoltageDC` → היחידה המשודרת `Volt`.

## פתוח

- **טרם אומת מול חומרה.** כל התשובות במסמך מגיעות מהמדריך.
- **הפעלת מוצא מרחוק לא מחווטת לפקודה מהאפליקציה** — כמו בכל שאר המקורות כאן.
- **בחירת `OUTP:ISEL`** (מוצא רגיל מול סליל 1000A) לא מחווטת. הבונה קיים ומסומן.
- ה-BL קורא setpoint של פונקציה אחת בלבד לפי ה-`Sensor` המוגדר; מכשיר שמוגדר לפונקציה אחרת בפועל
  יראה setpoint לא נכון. הלוג מדפיס את היחידה שהמודד מדווח לצד היחידה שמההגדרות — אי-התאמה ביניהן
  היא בדיוק סוג התקלה שאחרת מופיעה כמספר שגוי אבל סביר למראה.
